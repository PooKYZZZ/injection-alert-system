## 3. Findings ordered by severity

### Critical

1. Test and contract proof is not trustworthy enough to support merge.
- `frontend/app/(auth)/login/page.test.tsx` was failing completely during Batch 2, leaving the revised sign-in flow unproven.
- `frontend/app/api/bff-routes.test.ts` encodes at least one impossible/wrong internal-auth status contract (`401 INTERNAL_SERVICE_AUTH_FAILED`) while `frontend/lib/bff-client.ts` maps internal auth failures to `500 INTERNAL_SERVICE_AUTH_FAILED`.
- `tests/unit/test_eval_metadata.py` contains vacuous assertions and swallowed failures.
- `tests/integration/test_api.py` contains conditionally non-executing assertions and does not adequately prove the new action route end to end.

2. The branch introduces architecture-boundary duplication in runtime model loading.
- `distillbert/services/model_service.py` duplicates `web_app/services/model_service.py` behavior with no clear ownership or demonstrated runtime necessity.
- This creates two sources of truth for model artifact loading and metadata interpretation.

3. Operator-facing semantics are misleading in multiple places.
- ML health UI claims values are derived from traffic volume when the view-model does not use traffic volume for those policy bands.
- ML health shows a strong `Live Serving` label without freshness/staleness proof.
- Dashboard `High alerts` uses `actionable_alerts` while comparing against `prev_high_alert_count`, which is a metric mismatch.

### High

4. The new alert action path is under-tested and has split validation/error semantics.
- Integration coverage for `PATCH /api/alerts/{id}/action` is incomplete.
- Route-level ID validation and BFF-level ID validation are not aligned.
- BFF error mapping for action updates diverges from shared retry-aware handling.
- Presentation schema imports `AlertAction` from an application use-case module, which is a layering drift.

5. Auth/sign-in flow still has unresolved correctness and operator-flow issues.
- `frontend/components/SignInToast.tsx` can silently fail when `window.open` is blocked but returns `null`.
- `callbackUrl` intent is generated by the toast but not consumed by the login action path.
- `frontend/auth.ts` hardens secrets correctly, but this is an availability-sensitive startup change without evidence that all environments are ready.

6. Cross-surface alert counts and labels are semantically inconsistent.
- Top bar counters are global while nearby table counts are filtered/page-scoped.
- Sidebar alert badge uses a different scope again.
- Row open auto-triages `new/null` alerts to `in_review`, which changes visible counts as a side effect of inspection rather than explicit analyst action.

7. `.env.example` now misstates the model runtime boundary.
- It points `MODEL_PATH` and `MODEL_REGISTRY_PATH` to `web_app` while docs and runtime contract still center `ml_model/model_registry/...`.
- This is setup drift that can hide broken local configuration behind mock fallback behavior.

### Medium

8. The branch contains substantial refactor theater and non-local noise.
- ML health decomposition moved logic into new helpers/modules, but large amounts of dead CSS remain.
- Frontend styling and asset churn are mixed into functional remediation.
- Two new assets are apparently unused and increase merge noise.

9. Script-side validation can report false-green outcomes.
- `scripts/attack_dataset_tester.py` succeeds on transport success rather than label quality.
- An explicitly missing dataset path can silently fall back to a tiny fixture dataset.
- Candidate dataset search includes training data as a fallback, which can bias ad hoc quality checks.

10. `.gitignore` now hides source-adjacent generated model artifacts under `web_app/`.
- The ignore rules are targeted rather than blanket, but in combination with `.env.example` they make undocumented runtime-artifact drift easier to hide.

11. Several tests are too narrow, too coupled to old implementation details, or too weak for the claimed safety level.
- `frontend/features/alerts/queries.test.tsx` is too narrow for mutation safety.
- `frontend/components/SignInToast.test.tsx` misses fallback redirect behavior.
- `frontend/components/layout/AlertsNavItem.test.tsx` is shallow and contains drift indicators.
- `frontend/components/dashboard/TimelineChart.test.tsx` is mostly structural and heavily mocked.

### Low

12. Some UI wording and fallback semantics are likely misleading even where no direct bug is proven.
- `ActionLabel` renders `null` as `Unavailable`, which may not match actual analyst meaning.
- Dashboard alerts-table footer wording can be read as total-count semantics when it only reflects loaded rows.
- Recent alerts preview uses checkboxes without meaningful selection semantics.

## 4. Cross-batch patterns of concern

1. Truthfulness problems recur.
- ML health overclaims liveness and derivation.
- Alert/count surfaces present unlike metrics as if they were comparable.
- Auth flow suggests callback-return behavior that is not actually implemented.

2. Tests do not reliably defend the changed contracts.
- Some tests fail.
- Some tests assert the wrong behavior.
- Some tests are vacuous or conditional.
- The net effect is weak proof, not defense in depth.

3. Boundary discipline is inconsistent.
- Presentation schema depends on an application use-case type.
- Runtime model-service logic exists in two places.
- `.env.example` and `.gitignore` suggest a `web_app` artifact boundary that the docs and packaging flow do not support.

4. The branch is not scoped.
- Functional remediation is mixed with broad UI restyling, asset replacement, global CSS changes, model packaging drift, and new scripts.
- This raises merge risk even where any single isolated change might have been tolerable.

5. Operator-facing semantics are changed faster than the proving harness.
- New action path, revised sign-in guidance, count semantics changes, and ML-health rewrite all shipped with insufficient or contradictory validation.

## 7. Final merge recommendation

**Recommendation: do not merge**

Reasoning:
- Unresolved correctness issues remain in auth flow, alert-action proof, and cross-surface alert semantics.
- Tests are not in a trustworthy state for the changed contracts; some are failing, some are contradictory, and some are vacuous.
- ML-health and dashboard surfaces contain misleading semantics that are unsafe for an operator-facing system.
- Architecture and setup drift remain unresolved around model-service duplication, runtime artifact location, and env/config guidance.
- The branch is too noisy and insufficiently scoped for safe hostile-audit acceptance.

This is not a `merge after minor fixes` case. The problems are not cosmetic and not isolated to one file or one failing test. The branch needs a disciplined correction pass before it is fit for merge.
